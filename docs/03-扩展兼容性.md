# 03 · 扩展兼容性（WebView2 的边界与我们的补齐）

> 面向使用者与维护者。结论先行：**能装 Chrome / Edge 商店的扩展，但不能完全兼容所有扩展**——
> 这是 WebView2 平台的能力边界，不是安装链路的问题。
>
> 安装能力见 `browser://extensions`；实现细节见 `ARCHITECTURE.md` 与 `arch/lookup.md`。

---

## 1. 安装链路（已实现）

| 能力 | 说明 |
|---|---|
| 商店链接 / ID 直装 | 粘贴 Chrome 网上应用店或 Edge 加载项的详情页链接，或直接填 32 位扩展 ID。宿主按商店的更新接口下载 `.crx`。 |
| 本地 `.crx` | 下载后即按同一流程安装。 |
| 已解压目录 | 选择包含 `manifest.json` 的目录；会先复制进受管目录再加载。 |
| 签名校验 | CRX3 用包内公钥验签（RSA / ECDSA），CRX2 兼容 SHA-1 / SHA-256；签名不对直接拒绝，不落盘。 |
| 扩展 ID 一致 | 由公钥算出 Chrome 同款 ID，并把公钥写回 manifest 的 `key`，避免「换目录 ID 就变」。 |
| 受管目录 | `%LOCALAPPDATA%\sc-browser\Extensions\<id>\<版本>\`；安装索引在 `Extensions\index.json`。 |
| 元数据 | 自己解析 manifest：多语言名称（`_locales`）、描述、版本、Manifest 版本、权限、图标、弹窗、选项页、`update_url`。 |
| 安装前确认 | 列出该扩展申请的权限，用户确认后才加载。 |
| 自动更新 | **未实现**（只解析 `update_url` 并展示）。 |

> ⚠️ 本项目没有商店审核：安装扩展等于信任其代码。请只装可信来源的扩展。

---

## 2. 平台能力对照

WebView2 是一个「嵌入控件」，不是一个完整浏览器。官方明确表示不提供标签 / 窗口层面的 UI 与 API，
因此下面这些是**平台级缺失**，需要我们在宿主侧补：

| Chrome 扩展能力 | WebView2 | 我们的处理 |
|---|---|---|
| 内容脚本 / 后台 service worker / `chrome.storage` / `chrome.runtime` / `chrome.i18n` | ✅ 支持 | 无需处理 |
| `chrome.declarativeNetRequest` / 请求拦截类 | ✅ 支持（Chromium 内核） | 无需处理 |
| 工具栏图标 + 弹窗（`action.default_popup`） | ❌ 没有工具栏 | **已补**：工具栏按 manifest 图标生成按钮；点开由宿主开一个同 profile 的 WebView2 弹窗加载 `chrome-extension://<id>/<popup>` |
| 选项页（`options_page` / `options_ui`） | ✅ 页面本身可加载 | 扩展页提供「选项」按钮，在新标签打开 |
| `chrome.tabs` / `chrome.windows` | ❌ 不提供 | **部分补丁**：仅在我们承载的扩展弹窗里注入兼容层，覆盖 `tabs.query` / `getCurrent` / `create` / `update` 与 `windows.getCurrent`；后台 service worker 拿不到 |
| `chrome.action.onClicked`（没有弹窗时点图标） | ❌ 无入口 | 未实现（没有弹窗的扩展点了图标没反应） |
| 原生消息（native messaging） | ❌ 不支持 | 无 |
| 扩展之间互相通信 / 商店内购 | ❌ 无商店 | 无 |
| 无痕窗口中的扩展 | ⚠️ 未实测 | 无痕使用的是另一个 profile，扩展列表独立；实测后再补文档 |
| 扩展自动更新 | ❌ 平台不提供 | 未实现 |

## 3. 常见扩展兼容性（实测状态）

> **当前状态：均未实机验证。** 下表按「它依赖哪些 API」给出预期，验证后请把「预期」改成实测结果。
> 验证方法见第 4 节。

| 扩展 | 依赖 | 预期 | 实测 |
|---|---|---|---|
| uBlock Origin Lite | 内容脚本 + DNR + 弹窗 | 可用（弹窗能显示统计；`tabs.query` 由兼容层提供） | 未实测（商店包验签已通过） |
| Dark Reader | 内容脚本 + 弹窗 + 选项页 | 可用 | 未实测 |
| 沉浸式翻译 | 内容脚本 + 弹窗 + `tabs` | 弹窗可能部分可用 | 未实测 |
| Tampermonkey | 内容脚本 + 后台 + `tabs` | 脚本注入预计可用；管理页依赖后台的 tabs 能力，可能不完整 | 未实测 |
| Bitwarden / 1Password | 弹窗 + 后台 + 原生消息 | 弹窗可显示；**自动填充/原生消息不可用** | 未实测 |
| 广告拦截类（MV2，如 uBlock Origin） | MV2 后台页 | Chromium 131 仍支持但已弃用，随时可能失效 | 未实测 |

## 4. 怎么验证一个扩展

1. `browser://extensions` → 粘贴商店链接或 ID → 确认权限后安装。
2. 打开一个目标站点，看内容脚本是否生效（页面变化 / 图标角标）。
3. 点工具栏上的扩展图标：
   - 弹窗能打开且不是白屏 = 弹窗宿主正常；
   - 弹窗里能读到当前标签信息 = `chrome.tabs` 兼容层生效；
   - 白屏通常意味着它依赖未实现的 API（打开弹窗的 DevTools 看报错：右键弹窗 → 检查，或 F12）。
4. 看日志：`sh manager.sh logs`（安装、验签、加载失败都会记录）。

## 5. 已知边界与后续

- **后台 service worker 无法打补丁**：依赖后台 `chrome.tabs` 的扩展只能部分工作。
- **没有 `chrome.action.onClicked`**：没有弹窗的扩展点击图标无反应；后续可在宿主侧补一个「点击事件」通道。
- **无痕窗口的扩展行为未验证**。
- **自动更新未实现**：可以手动重新安装新版。
