# 一、部署

## 1. 怎么启动

### 1.1 前置条件

| 依赖 | 用途 | 是否必须 |
|---|---|---|
| Windows 10 1809+ / Windows 11 | WPF 与 WebView2 的运行平台 | ✅ 必须 |
| .NET 10 SDK（自行构建时） | 编译源码 | ✅ 构建时必须；用发布版自包含包时不需要 |
| WebView2 运行时 | 承载网页内容 | ✅ 必须（Win10/11 通常已随 Edge 预装；缺失时从微软官网安装 Evergreen 运行时） |

> ⚠️ WebView2 运行时缺失的典型现象：窗口能打开但内容区一直空白。
> 此时安装「Evergreen WebView2 Runtime」即可，无需改动本应用。

### 1.2 配置

本项目**无需任何密钥或环境变量**。所有可调项都在应用内的 `browser://settings` 页面，
落盘于 `%LOCALAPPDATA%\sc-browser\settings.json`。

### 1.3 启动

```bash
sh manager.sh run
```

首次启动会：
1. 建立数据目录 `%LOCALAPPDATA%\sc-browser`（含 `UserData`、`Extensions`、`logs`）；
2. 初始化 SQLite（`browser.db`）；
3. 打开一个新标签页。

> ⚠️ **首次启动较慢**属正常：要初始化 WebView2 运行时与用户数据目录。
> 另外，若上次退出时开着很多标签且启用了「启动时恢复」，会逐个创建 WebView2，启动时间随标签数上升
> （这是当前已知的待优化项，见 `ROADMAP.md` P1-4）。

## 2. 怎么用（核心功能）

### 2.1 基本浏览

- 地址栏输入：既能识别网址（`example.com` 自动补 `https://`），也能当搜索框用。
- 工具栏：后退 / 前进 / 刷新（加载中变为「停止」）/ 主页 / 收藏星标 / 主菜单。
- 地址栏左侧图标表示连接安全性（锁 / 信息 / 警告）。

### 2.2 快捷键

| 快捷键 | 作用 |
|---|---|
| `Ctrl+T` / `Ctrl+W` | 新建 / 关闭标签页 |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 下一个 / 上一个标签页 |
| `Ctrl+1` ~ `Ctrl+8` / `Ctrl+9` | 跳到第 N 个 / 最后一个标签页 |
| `Ctrl+L` / `Alt+D` | 聚焦地址栏（聚焦即全选） |
| `Alt+←` / `Alt+→` | 后退 / 前进 |
| `F5` / `Ctrl+R` | 刷新 |
| `Ctrl+Shift+R` | 忽略缓存刷新 |
| `Ctrl+D` | 收藏当前页 |
| `Ctrl+H` / `Ctrl+J` | 历史记录 / 下载内容 |
| `Ctrl+±` / `Ctrl+0` | 放大缩小 / 恢复 100% |
| `Ctrl+F` | 页内查找（输入即搜；`Enter` / `Shift+Enter` 或 `F3` / `Shift+F3` 跳转，`Esc` 关闭） |
| `Esc` | 地址栏编辑中按下 = 放弃编辑；页面加载中 = 停止 |

> 💡 焦点在网页里时这些快捷键同样有效（已实测）。

### 2.3 扩展程序

在 `browser://extensions` 页面：

- **加载已解压的扩展**：选择扩展的**顶层目录**（即直接含 `manifest.json` 的那一层）。
- **安装 `.crx` 包**：选择 `.crx` 文件，应用会先解包到 `%LOCALAPPDATA%\sc-browser\Extensions` 再加载。
- 每个扩展可**启用/停用**或**移除**；改动立即对所有已打开页面生效。

> ⚠️ **安装后不要改动扩展目录内的文件**——WebView2 检测到内容变化会把这个扩展自动卸载。
> 开发扩展时的正确循环是：改完代码 → 重新安装（移除后重装）。
>
> ⚠️ 本应用**没有扩展商店、不校验签名、不自动更新**。装扩展等于信任其代码，请自行把关来源。
>
> ⚠️ 部分依赖浏览器专有能力的扩展（如 `chrome.tabs`、部分后台页 API）可能无法完整工作——
> 这是 WebView2 平台的能力边界，不是本应用的缺陷。

### 2.4 命令行安装扩展

便于批量部署或自动化验证：

```bash
ScBrowser.exe --install-extension "D:\path\to\unpacked-extension"
ScBrowser.exe --install-extension "D:\path\to\extension.crx"
```

安装结果记入日志（`sh manager.sh logs`）。

### 2.5 设置

`browser://settings` 覆盖：主题（跟随系统/浅色/深色，**即时生效**）、搜索引擎模板、主页、
启动恢复会话、下载目录、扩展总开关（**改动需重启**）、清除浏览数据（缓存 / Cookie / 站点数据）。

# 二、维护

## 3. 数据 / 配置文件在哪

全部位于 `%LOCALAPPDATA%\sc-browser`（可用 `sh manager.sh data` 查看）：

| 文件 / 目录 | 内容 |
|---|---|
| `browser.db`（含 `-wal` / `-shm`） | 历史记录、书签、下载记录（SQLite） |
| `settings.json` | 应用设置 |
| `session.json` | 上次退出时的标签页（用于会话恢复） |
| `UserData/` | WebView2 用户数据：Cookie、缓存、站点存储、**已安装扩展的安装态** |
| `Extensions/` | 由本应用管理的扩展目录（`.crx` 解包产物） |
| `logs/` | Serilog 日志，按天滚动，保留 7 天 |

## 4. 备份 / 迁移 / 重置

- **备份**：整个 `%LOCALAPPDATA%\sc-browser` 目录拷走即可（含书签、历史、设置、扩展、登录状态）。
- **迁移**：把上述目录复制到目标机器的同一路径。
- **重置**：`sh manager.sh reset`（会二次确认），等价于删除整个数据目录。

> ⚠️ 重置会一并删除 Cookie 与登录状态。

## 5. 构建 / 发布

| 操作 | 命令 | 产物 |
|---|---|---|
| 构建（Debug） | `sh manager.sh build` | `src/ScBrowser/bin/Debug/net10.0-windows/` |
| 构建（Release） | `sh manager.sh release` | `src/ScBrowser/bin/Release/net10.0-windows/` |
| 打包（dev + release） | `sh manager.sh package`（或 `package.bat`） | `dist/dev/`、`dist/release/` |

打包产物（统一放在 `dist/`）：

- `dist/dev/ScBrowser_<版本>_x64-unpack-debug.zip`：Debug 免安装包（框架依赖），
  含 PDB、`logs/` 与 `build-info.txt`；zip 内带单一根目录
  `ScBrowser_<版本>_x64-unpack-debug/`；运行它的机器需要 .NET 10 桌面运行时。
- `dist/release/unpack/`：Release 免安装目录（自包含），
  目标机不需要 .NET 运行时；目录里的 `ScBrowser.exe` 可直接双击运行。
- `dist/release/ScBrowser_<版本>_x64-unpack.zip`：上述目录的压缩包；
  **zip 根下直接是程序文件，不再套一层版本目录**，解压即可运行。
- `dist/release/ScBrowser_<版本>_x64-setup.exe`：Windows 安装程序，按用户安装到
  `%LOCALAPPDATA%\Programs\ScBrowser`，**不会**删除 `%LOCALAPPDATA%\sc-browser`
  下的书签、历史、Cookie 等用户数据。

> dev 的 zip 内带单一根目录，release 的 zip 不带顶层目录。
> `sh manager.sh clean` 只清 bin/obj 与旧产物，会保留 `dist/` 成品包。

> 💡 自包含 unpack 包体积较大（含 .NET 运行时），但换机器免装运行时。
> 若目标机已装 .NET 10 桌面运行时，用 `sh manager.sh release` 的产物即可，体积小得多。

# 三、调试

## 6. 打不开 / 内容区空白

按顺序自查：

1. 窗口能开、内容区全白 → 极可能是**缺 WebView2 运行时**。安装 Evergreen WebView2 Runtime 后重试。
2. WebView2 运行时已装但仍空白 → 看日志：`sh manager.sh logs`，搜 `[ERR]` / `[FTL]`。
3. 只是某些网站打不开 → 看该标签页顶部的红色错误条（会显示 `WebErrorStatus`）。
4. 想确认内部页面本身有没有报错 → 在内容区按 `F12`（DevTools 已开启），看 Console。

## 7. 扩展装了但页面没反应

1. 到 `browser://extensions` 确认扩展在列表里且**开关是开的**。
2. 重新加载页面——扩展在页面加载时注入，已打开的旧页面不会追溯生效（启停开关除外）。
3. 确认扩展的 `manifest.json` 里的 `matches` 覆盖了目标站点，且权限声明完整。
4. 用 `samples/extensions/hello-sc-browser` 做对照：它会在每个页面右下角注入一个蓝色角标，
   角标出现即说明扩展机制正常，问题出在那个具体扩展上。
5. 注意：改动扩展目录内文件会导致扩展被自动卸载，回列表看是否已消失。

## 8. 常见问题（FAQ）

**Q：为什么 `.crx` 安装后，`Extensions` 目录里的文件夹名和扩展 ID 不一样？**
A：目录名由 `.crx` 文件名派生（做了安全字符规整）。扩展 ID 由 WebView2 依据扩展内容计算，
两者没有对应关系，属正常。

**Q：为什么地址栏显示 `browser://settings` 而不是 `file://...`？**
A：内部页面在 WebView2 眼里确实是本地 `file://` 路径，但展示层做了逻辑地址映射，让用户看到伪协议地址。

**Q：能装 Chrome 应用商店的扩展吗？**
A：不能直接装。需要在 Chrome 里把扩展下载为 `.crx`（或用「打包扩展程序」得到 `.crx`/目录），
再在 `browser://extensions` 中安装。部分依赖浏览器专有 API 的扩展仍可能功能不全。

**Q：为什么每个标签页都占内存？**
A：每标签页一个 WebView2 是刻意取舍——换来切换零延迟和页面状态保留（滚动位置、表单、播放中的视频），
与 Chrome 的进程模型一致。

**Q：改了代码怎么快速验证某个内部页面？**
A：往 `%LOCALAPPDATA%\sc-browser\session.json` 写
`{"Urls":["browser://extensions"],"ActiveIndex":0,"SavedAt":"2026-10-16T00:00:00+00:00"}` 再启动应用，
会直接落在该页面。

## 9. 怎么跑测试 / 看测在哪

```bash
sh manager.sh test
```

测试位于 `tests/ScBrowser.Tests/`，当前覆盖两块最易回归的纯逻辑：

- `AddressBarResolverTests`：地址栏输入判定（网址 / 裸域名 / 搜索词 / 内部页面 / 编码）。
- `CrxPackageTests`：CRX v2/v3 头解析、解包、重装清空、坏文件、**目录穿越防护**、目录名规整。

> 涉及 UI 与 WebView2 的行为改动（外壳交互、导航事件、扩展注入）无法靠单测覆盖，
> 请按第 6~8 节的实跑方式验证。
