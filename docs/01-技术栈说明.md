# 01 · 技术栈说明

> 面向使用者/维护者：本项目用了哪些技术、为什么这么选、各自负责什么。
> 代码在哪、怎么连，见 [`../ARCHITECTURE.md`](../ARCHITECTURE.md)。

## 总览

| 用途 | 选型 | 为什么 |
|---|---|---|
| 运行时 | .NET 10（`net10.0-windows`） | 当前唯一在维护的 LTS；.NET 9 已 EOL、.NET 8 于 2026-11 EOL。桌面应用可直接拿到 WindowsDesktop 运行时 |
| 外壳 UI | WPF（XAML） | 矢量渲染 + 数据绑定 + 样式系统，界面表现力上限高；原生控件在焦点/输入法/无障碍/DPI 上比自绘省心 |
| 网页内容与内部页面 | Microsoft Edge WebView2（`Microsoft.Web.WebView2` 1.0.4258.31） | 微软官方一等公民控件，与系统 Edge 同源、随系统更新；同时是「Chrome 扩展支持」唯一可行路径 |
| 内部页面 UI | 原生 HTML / CSS / JavaScript（无构建、无打包） | 与 Chrome 的 `chrome://` 页面同构；复用本栈里的 JS 半边，改版快、无需编译 |
| 数据存储 | SQLite（`Microsoft.Data.Sqlite`） | 历史需要按时间倒序分页、按关键字检索、按访问次数取热门项——这些都是 SQL 几行的事 |
| MVVM 基建 | CommunityToolkit.Mvvm | 源生成器消除 `INotifyPropertyChanged` / `ICommand` 样板，是微软维护的事实标准 |
| 依赖注入 / 宿主 | `Microsoft.Extensions.Hosting` + `DependencyInjection` | 分层架构下统一组装服务、统一生命周期；配置与日志也顺手拿到 |
| 日志 | Serilog（File + Debug sink） | 桌面应用出问题没有控制台可看，按天滚动落盘 + 保留 7 天是刚需 |
| 测试 | xUnit | 覆盖纯逻辑（地址栏解析、CRX 解包），这两块最容易回归 |

## 各组件职责分工

- **WPF 外壳**：标签条、工具栏、地址栏、主菜单。**只负责呈现与转译用户意图**，不承载网页。
- **WebView2**：承载两类内容——① 用户访问的网页（每标签页一个实例）；② 应用自带的内部页面（WebUI）。
- **C# 宿主服务层**：历史/书签/下载的持久化、扩展管理、设置、主题、会话、下载接管。
- **消息桥**：WebUI 与宿主之间唯一的通信通道（`WebMessageRouter` ↔ `common/browser-api.js`）。
- **SQLite**：历史、书签、下载三类记录的落盘，位于 `%LOCALAPPDATA%\sc-browser\browser.db`。

## 与参考项目 WebView2Browser（C++）的关键差异

| 维度 | 参考项目（C++ Win32） | 本项目（C# WPF） | 原因 |
|---|---|---|---|
| 外壳 UI | **第二个 WebView 环境**跑 HTML | **WPF 原生控件** | 省掉一整套 UI 环境与两个 WebView 实例；系统集成更省心。Chrome/Edge 的外壳同样是原生自绘 |
| 环境数量 | 2 个（UI 环境 + 内容环境） | **1 个** | 外壳不再需要 WebView，隔离层随之消失 |
| 架构 | 逻辑集中在 `BrowserWindow` 一个类里 | 引擎层/存储层/服务层/视图层分层 + DI | 可测试、可替换、上下文友好 |
| JSON | cpprestsdk | `System.Text.Json` | 内置、更快、无第三方依赖 |
| 存储 | 控件 WebView 里的 IndexedDB | SQLite | 可 SQL 查询、容量无顾虑、与宿主同进程管理 |
| 跨 WebView 通信 | `PostWebMessageAsJson` + 手写 JSON | 同一套机制，但收敛为**一个路由器 + 一套协议** | 新增内部页面只需加一个 `case` |
| 错误处理 | `RETURN_IF_FAILED` + 手动 COM 引用计数 | C# 异常 + GC + 全局兜底 | 样板大幅减少 |

## 关键平台约束（选型时必须知道）

1. **WebView2 只能加载「解包扩展」**（含 `manifest.json` 的目录），不能直接安装 `.crx`。
   本项目为此实现了 CRX 解包（v2/v3 头解析 + ZIP 提取 + 目录穿越防护）。
2. **扩展需要 `AreBrowserExtensionsEnabled = true`**，且该开关属于**环境创建期参数**，改动需重启应用。
3. **扩展按 profile 管理**，而 profile 只能从已初始化的 `CoreWebView2` 实例上取，因此要求至少有一个标签页就绪。
4. **扩展内容不会被复制到用户数据目录**——安装后改动扩展目录内的文件会导致该扩展被自动卸载。
5. **WebView2 是 HWND 控件（airspace）**：任何 WPF 元素都无法绘制在其之上，浮层必须使用独立顶层窗口。

## 配置与运行

- 用户可调参数集中在 `%LOCALAPPDATA%\sc-browser\settings.json`（由设置页读写，`Services/SettingsService.cs` 是代码侧单一源）。
- 落盘路径统一由 `Infrastructure/AppPaths.cs` 定义，禁止各处硬编码。
- 运行：`sh manager.sh run`；统一管理脚本 `sh manager.sh help`。
- 测试：`sh manager.sh test`；提交前闸门 `sh manager.sh verify`。
