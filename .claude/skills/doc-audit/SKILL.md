# doc-audit · 文档体系漂移体检

> **为什么需要它**：整套文档体系靠 AI 自觉维护，`check-docs.sh` 只能兜住机械项。跑久了 `ARCHITECTURE.md` 会与代码脱节、`HANDOFF.md` 会堆积历史、`CHANGELOG.md` 会漏记、`ROADMAP.md` 完成状态会失真。本 skill 是「手动兜底体检」：一次性把漂移点扫出来，交给用户决定修哪些。
>
> **何时用**：仅用户明确要求时（`/doc-audit`，或「审一下文档」「检查文档和代码对不对得上」「文档漂移查一下」）。**不自动触发**。
>
> **边界**：本 skill 只**发现问题 + 按确认修文档**，不改业务代码。发现「代码结构变了但图谱没跟上」时，是更新 `ARCHITECTURE.md`，不是改代码。

## 执行步骤

### 1. 采集现状（只读，先看再说）

- **先跑机械体检**：`sh check-docs.sh`——占位符 / 初始化块残留、根文档与 `CLAUDE.md` 导入、文档体量（按字符计，上限见 AGENTS §1.1）、CHANGELOG 疑似漏记，它会直接判出来，作为本次审计的起点。
- 读 5 份根文档（`AGENTS.md` / `ARCHITECTURE.md` / `ROADMAP.md` / `CHANGELOG.md` / `HANDOFF.md`）与 `docs/00-目录.md`；有 `arch/` 分册的，按 ARCH §0.5 路由逐份对照。
- 用 Glob / Grep 列出 `src/`（或该栈源码根）的顶层文件 / 目录与关键函数名，作为「真实代码现状」。
- 若近期有提交，`git log --oneline -20 -- .` 看本项目有没有「改了代码却没进 CHANGELOG」的迹象。

> 分工：`check-docs.sh` 只判**机械项**（能脚本化的）；本 skill 的价值在**语义漂移**——图谱的函数名 / 职责是否与代码对得上、信息是否放对了地方，这些脚本判不了，必须 AI 逐项核对。

### 2. 逐项对照（按下面清单打勾，逐条给结论）

| 检查项 | 怎么查 | 判为漂移的信号 |
|---|---|---|
| **占位符残留** | `check-docs.sh` 第 1 项 | 已初始化项目里还有任何一处 → 初始化没做干净 |
| **图谱↔代码：文件职责表** | ARCH §1 表里的文件 vs 实际顶层文件 | 表里有已删的文件，或有新文件没登记 |
| **图谱↔代码：任务→入口表** | ARCH §2 的函数名 vs grep 结果 | 表里函数已改名 / 删除，或常见改动的新入口没登记；或表被写成了全量函数表 |
| **图谱↔代码：作用域路由** | ARCH §0.5 路由涉及的文件 / 分册是否都存在 | 指向不存在的文件 / 模块 / 分册 |
| **ARCHITECTURE 体量与写法** | `check-docs.sh` 体量项 + 抽查单元格 | 超出 AGENTS §1.1 上限仍未拆分；单元格堆了日期、版本、改动经过 |
| **ROADMAP 状态失真 / 堆积** | ✅ 条目与「已交付里程碑」+ 体量 | 实际已完成的大块没打 ✅ / 没记里程碑；或大纲缺了新规划；或堆了实现细节（应归 CHANGELOG）；或已交付里程碑的条目还留在大纲里、超出体量上限 |
| **HANDOFF 堆积** | 体量 + 各小节内容 | 超出上限；「当前任务 / 进行中 / 下一步」残留已完成任务；「待验收」超过 5 条；出现长期知识（应迁 ARCH §7） |
| **信息放错位置** | 对照 AGENTS §5.0 去向表 | 长期的坑写在 HANDOFF、运行命令散落多处、改动经过写进 ARCHITECTURE 等 |
| **CHANGELOG 漏记 / 写法** | git log vs `[未发布]` / 版本区 | 有使用者可感知的改动没记入；条目写成长文；`[未发布]` 超过 15 条没提醒发版 |
| **交叉引用失效** | 各文档里的相对链接、文件名与「ARCH §x / AGENTS §x」 | 指向不存在的文件或章节（如 skill 指向已改名的 docs 篇章） |
| **docs 目录一致** | `docs/00-目录.md` vs `docs/` 实际文件 | 目录登记与实际文件对不上 |

### 3. 产出漂移清单（先报告，不擅自大改）

按严重度分组列给用户，每条含：**在哪个文件、什么漂移、建议怎么修**。

- **🔴 会误导后续迭代**：图谱与代码不符、占位符残留、交叉引用失效、ROADMAP 状态失真。
- **🟡 堆积 / 体量**：HANDOFF 超标、ARCHITECTURE 该拆未拆、信息放错位置、CHANGELOG 漏记。
- **🟢 小瑕疵**：措辞、格式、目录登记。

### 4. 按确认修复（只改文档）

- 用户确认后，逐条修文档；**图谱与代码不符时以代码为准**更新图谱。
- HANDOFF 堆积：核实 ROADMAP / CHANGELOG 已有记录后删除已完结内容；长期有效的坑与理由迁到 ARCH §7。
- ROADMAP 失真 / 堆积：按实际完成度补 ✅ / 里程碑，删掉误入的实现细节（细节转记 CHANGELOG）；已交付里程碑的大纲条目删掉，压成「已交付里程碑」里的一行。
- ARCHITECTURE 超标：按 AGENTS §1.1 拆分。
- 修完再跑一次 `sh check-docs.sh`，简述「修了哪几条、还剩哪些待用户决定」。

## 注意

- **不改业务代码**；只读代码用于对照。
- 拿不准「代码变了还是文档错了」时**先问用户**，别擅自改图谱掩盖真实问题。
- 密钥 / 内网地址不写进任何入库文档。
