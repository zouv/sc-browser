# init-docs · 手动初始化文档体系（自举兜底）

> **为什么需要它**：正常情况下，AI 首次进项目会读到 `AGENTS.md` 顶部的 `AI-INIT-START` 引导块自动初始化。但不同工具/较弱模型可能跳过那段注释，带着 `{{占位符}}` 继续干活，污染全链路。本 skill 是**显式手动入口**，把「自动自举」变成「一条命令可触发」，更稳。
>
> **何时用**：拷模板后发现文档里还有 `{{...}}` 或 `AI-INIT` 标记而 AI 没自举；或用户明确说「初始化文档」「init-docs」「把这套模板配好」。
>
> **已初始化就别跑**：grep 无 `{{` 且无 `AI-INIT` → 已初始化，直接当正常文档用，本 skill 应拒绝执行并告知用户。

## 执行步骤

> 权威流程写在 `AGENTS.md` 顶部的 `AI-INIT-START ... AI-INIT-END` 块，本 skill 是它的手动触发器与浓缩版。以那段为准，本文只做导航。

### 1. 先判定是否真未初始化

grep 项目根文档里的 `{{` 与 `AI-INIT`。都没有 → 已初始化，停止并告诉用户「无需初始化」。有 → 继续。

### 2. 收集信息（先问后填，技术栈必问）

一次性问用户（能可靠推断的给默认值让其确认）：
- 项目名（默认取仓库目录名）、一句话简介/架构、默认分支（默认 main）
- 运行命令 / 测试或校验命令 / lint 命令
- **技术栈（必问）**——决定 Python 脚手架去留，别因为模板是 Python 就默认新项目是 Python。

### 3. 脚手架决策闸门（三选一，见 AGENTS AI-INIT 步骤 2.5）

- **(A) Python/uv**：保留脚手架，只替换文本占位符（`{{PROJECT_NAME}}`/`{{ENV_PREFIX}}`/`{{PROJECT_DESC}}`/`{{AUTHOR}}`）；**`app_pkg` 是固定包名不是占位符，勿改**。
- **(B) 其它栈（C#/Node/Rust/前端…）**：删 `src/app_pkg/`、`pyproject.toml`、`tests/`、（不适用则）`.env.example`；重写 `manager.sh` 的 `uv run` 为该栈命令；按该栈惯例建工程文件。
- **(C) 纯文档/无代码**：删 `src/`、`pyproject.toml`、`tests/`，`manager.sh` 精简或删。

⚠ 绝不留「C# 项目却带着 pyproject.toml/uv 命令」这种半吊子残留。
⚠ `check-docs.sh` 技术栈无关（纯 bash），三种方案都**保留不删**。

### 4. 扫仓库生成骨架（文档体系技术栈无关，任何项目都做）

- `ARCHITECTURE.md`：填 §0 一句话架构+图、§1 文件职责表（每个顶层文件一行）、§0.5 作用域路由；§2 任务→位置表可先留 1~2 行示范或留空并注明随开发补全。
- `ROADMAP.md`：按仓库现状填「总进度」（一两句话）+「已交付里程碑」（首版功能，指向 CHANGELOG [0.1.0]）；「总体开发大纲」表可先留空行占位。
- `CHANGELOG.md`：把仓库现有主要功能写进 `[0.1.0]`（日期取今天）。
- `HANDOFF.md`：填元数据（项目名/分支/运行测试命令），状态置「无进行中任务」。
- `AGENTS.md`：补 §2 技术约束 / §3 安全铁律 / §4 验证命令。
- `docs/00`·`01`·`02`：替换占位符，用不到的小节删掉。

### 5. 自清理（关键，否则会重复初始化）

- 替换所有 `{{...}}` 为真实值（保留 Python 脚手架时 `app_pkg` 字面包名勿动）。
- 删所有 `<!-- 模板说明：... -->` 与「示例」引导行。
- 删各文档里整个 `AI-INIT-START ... AI-INIT-END` 块（含 AGENTS 顶部那段）。
- **删除 `_TEMPLATE_README.md`**。

### 6. 回报

简述：生成了哪些骨架、脚手架按哪种方案处理、哪些表留待后续补全。然后继续用户的原始请求。

## 注意

- 密钥/内网地址绝不写进任何入库文档，用占位符。
- 初始化只碰文档与脚手架结构，不擅自写业务逻辑。
